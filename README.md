# Telegram · GREEN-API

Минимальный Telegram-чат на React и TypeScript: подключение собственного инстанса GREEN-API, создание переписки по номеру телефона, отправка текста и получение ответов через HTTP API. Также есть автономный деморежим.

## Локальный запуск

Нужен **Node.js 22.12+** (в CI используется Node.js 24) и npm.

```bash
git clone https://github.com/asanaliwhy/Test-Frontend-TG.git
cd Test-Frontend-TG
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (обычно `http://127.0.0.1:5173`). Нажмите **«Открыть демо»**, чтобы посмотреть приложение без ключей: тестовые сообщения и ответы остаются в браузере.

## Подключение настоящего Telegram

1. Создайте **Telegram-инстанс** в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте в нём свой Telegram-аккаунт. Это интеграция аккаунта через GREEN-API, а не Telegram Bot API.
2. Скопируйте `idInstance`, `apiTokenInstance` и **`apiUrl` именно своего инстанса**. На экране подключения адрес находится в раскрывающемся разделе «Адрес API»; значение по умолчанию — пример хоста, его нужно сверить с кабинетом.
3. В настройках инстанса очистите `webhookUrl`, включите `incomingWebhook: yes` для входящих сообщений и `outgoingWebhook: yes` для статусов. Приложение читает настройки и подсказывает, что исправить, но не изменяет их.
4. Введите данные и нажмите «Подключиться». Инстанс должен находиться в состоянии `authorized`.
5. Нажмите «Новый чат» и введите номер получателя в международном формате, например `+7 700 123 45 67`. Поиск выполняется через `checkAccount`; переписка использует возвращённый `chatId`. Если номер скрыт настройками Telegram, API может не найти контакт.
6. Отправьте текст. Ответьте с аккаунта получателя в Telegram — ответ появится в этом же чате.

После изменения настроек инстанса сервису может понадобиться время для их применения. Затем нажмите «Повторить подключение» или переподключитесь.

**Используйте отдельный тестовый инстанс и одну вкладку клиента.** HTTP API использует общую очередь: подтверждённое уведомление удаляется из неё. Другой потребитель этой очереди может забрать ответы раньше этого приложения.

## Возможности

- Создание чата по номеру с нормализацией и защитой от повторного создания.
- Поиск чатов, непрочитанные сообщения и отдельный черновик для каждой переписки.
- Загрузка существующих чатов Telegram после подключения; кнопка обновления списка. При открытии переписки загружаются последние 100 сообщений, из которых показываются текстовые. История объединяется с новыми ответами без дубликатов и повторно не запрашивается при переключении в рамках сессии.
- Текст до 4096 символов; Enter отправляет, Shift + Enter переносит строку.
- Состояния отправки, очереди, доставки, прочтения и ошибки. Успешный `sendMessage` означает постановку в очередь, а не гарантированную доставку.
- Последовательный long polling: `receiveNotification` → обработка → `deleteNotification`. Повторные уведомления не создают дубликаты сообщений. Неиспользуемые типы событий подтверждаются и пропускаются, чтобы очередь продолжала двигаться.
- Переподключение с увеличением интервала при сетевых сбоях; остановка при ошибках авторизации.
- Ограничение частоты служебных запросов, включая повторное монтирование React StrictMode; до двух повторов чтения при HTTP 429 с учётом доступного Retry-After. Отправка сообщений автоматически не повторяется.
- Адаптивная навигация, доступные подписи, видимый фокус и поддержка reduced motion.

## Проверки и сборка

```bash
npm run lint       # ESLint и правила React hooks
npm test           # Vitest, однократный прогон
npm run test:watch # Тесты в режиме наблюдения
npm run build      # TypeScript + production-сборка Vite
npm run preview    # Просмотр собранного приложения
npm run check      # Линтер, тесты, сборка
```

GitHub Actions запускает `npm ci` и `npm run check` при push и pull request. Статические файлы для хостинга находятся в `dist/`; приложение не требует сервера Node.js после сборки. Развёртывание в этой работе не настроено.

## Устройство проекта

```text
src/api/          Типы и HTTP-клиент GREEN-API
src/chat/         Reducer, обработка событий, polling, жизненный цикл сессии, демо
src/components/   Подключение, список чатов, новый чат, сообщения, ввод
src/lib/          Валидация и ограничения Telegram
```

Состояние переписок хранится в React reducer. Сетевые события преобразуются в действия отдельно от компонентов. Отправка сообщения и получение уведомлений имеют отдельные контроллеры отмены: перезапуск polling не обрывает уже отправляемый текст.

## Ограничения и данные

- Только текстовые сообщения. Список включает доступные API личные и групповые чаты; управление группами и вложения не реализованы. История ограничена последними 100 сообщениями выбранного чата; более ранняя история не подгружается. Постоянная синхронизация исходящих сообщений с других клиентов не реализована, но доступные исходящие тексты показываются из загруженной истории.
- Токен, сообщения и черновики хранятся только в памяти вкладки. Выход и обновление страницы очищают сессию. Нет `localStorage`, `sessionStorage`, аналитики или серверной базы данных.
- Это браузерный клиент: введённый ключ виден владельцу браузера в сетевых запросах к GREEN-API. Не используйте публичный общий токен и не записывайте ключ в исходники или `VITE_*` переменные.
- При потере ответа `sendMessage` отправка могла уже произойти. Автоматического повтора отправки нет; перед ручным повтором проверьте Telegram.
- Шрифт Manrope загружается с Google Fonts; при недоступности используется Segoe UI. Токены и тексты сообщений не передаются сервису шрифтов.
- Реальный обмен с Telegram требует ваших действующих учётных данных. Проверки с подменённым API не подтверждают доступность инстанса, его тариф или настройки конкретного аккаунта.
