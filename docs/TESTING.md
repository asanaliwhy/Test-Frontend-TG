# Проверки

## Автоматические

`npm run check` запускает линтер, 34 теста Vitest и production-сборку.

| Область | Что проверяется |
| --- | --- |
| Валидация | Международные номера, формат ключей, разрешённый HTTPS-хост, лимит 4096 символов |
| HTTP-клиент | Формат sendMessage, canonical chatId, пустой polling-ответ, DELETE-подтверждение, безопасные ошибки |
| Состояние чатов | Повторные уведомления, непрочитанные, порядок сообщений, повторное открытие, очистка |
| Статусы | Отсутствие отката read → sent; статус, пришедший раньше HTTP-ответа отправки |
| Polling | Обработка перед удалением, backoff, отказ подтверждения, остановка при 401, поздний ответ после выхода |

## Браузерная проверка при реализации

Проверено 16 октября 2026 года в Chromium через Playwright CLI.

- Деморежим: отправка текста, синтетический ответ, отсутствие дубликатов.
- Мобильная навигация между чатами, сохранение черновика при переключении.
- Полный сценарий с подменённым GREEN-API: подключение → поиск номера → чат → Enter → исходящее сообщение → статус read → входящий ответ → повторная доставка того же события → выход.
- В запрос отправки передан именно `chatId`, возвращённый поиском. Уведомления 1, 2 и 3 подтверждены; повторное входящее сообщение не продублировано.
- После выхода поле токена пустое; localStorage и sessionStorage не используются. В проверяемом сценарии не возникло JavaScript runtime errors.
- Визуальная проверка подключения и чата при 1440×960 и 390×844. Обнаруженные конфликт React-ключей и переполнение списка исправлены отдельным коммитом.

Это проверка с синтетическими ответами. **Живой Telegram-инстанс не проверен:** действующие учётные данные не предоставлялись.

## Ручная проверка с настоящим инстансом

1. Подготовить отдельный авторизованный Telegram-инстанс и включить уведомления по README.
2. Открыть приложение в одной вкладке и ввести его ID, токен и apiUrl.
3. Создать чат с известным тестовым получателем по номеру. Повторно ввести тот же номер с пробелами — должна открыться существующая переписка.
4. Отправить текст и переносы строк. Убедиться, что получатель видит сообщение в Telegram.
5. Ответить из Telegram. Проверить, что ответ появился в той же переписке ровно один раз.
6. Переключиться на другой чат и отправить ещё один входящий ответ — у первого чата должна появиться отметка непрочитанных; при открытии она очищается.
7. В DevTools временно включить Offline. Приложение должно показать переподключение; после Online — продолжить получение.
8. Попытаться отправить при потере сети. Проверить видимое сообщение об ошибке и отсутствие автоматической повторной отправки.
9. Выйти и снова открыть подключение. Переписка, черновики и токен не должны сохраняться.

Дополнительно: неверный токен, неавторизованный инстанс, скрытый номер Telegram, лимиты тарифа и внешний webhook. Сообщения этих сценариев зависят от состояния реального аккаунта и требуют отдельной проверки.
